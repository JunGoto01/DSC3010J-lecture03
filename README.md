## まず、データコンペとは

データコンペは、全員が同じ予測問題に取り組み、答えを提出して精度を確かめる活動です。Kaggleは、そのようなデータ分析・機械学習コンペを行うWebサービスの一つです。

この授業では、Kaggleそのものではなく、次の小さな模擬コンペを行います。

1. 正解つきの`train`を受け取る
2. `train`を調べ、正解を予測する規則を作る
3. 正解を隠した`challenge`へ同じ規則を使う
4. 270人分の0/1予測をCSVで提出する
5. 採点サーバーが隠された正解と比べ、Accuracyを返す
6. 一つだけ改善案を試し、もう一度提出する

Accuracyは、次の単純な割合です。

```text
Accuracy = 正しく予測できた人数 ÷ 270人
```

たとえば189人を正しく予測できれば、Accuracyは`189 ÷ 270 = 0.700`です。

## なぜコンペでpipelineを学ぶのか

目的はランキングで1位になることだけではありません。正解を知らない人を予測するには、次の作業を最初から最後までつなぐ必要があります。

```text
問いを決める
    ↓
trainを読み、人数・列・欠損を確かめる
    ↓
使う変数と使わない変数を決める
    ↓
正解との関係を表で見る
    ↓
trainから予測規則を学ぶ
    ↓
challengeの確率を出し、0/1へ変える
    ↓
PassengerIdと予測をCSVにして提出する
    ↓
scoreを見て、一つの仮説だけを試す
```

この一連の流れを、データ分析の`pipeline`と呼びます。最後にCSVを提出するため、途中の一工程だけでなく、読み込みから出力までが本当につながっているかを確かめられます。

## 二つの表

| 表 | 人数 | 乗客情報 | 正解`Survived` |
|---|---:|---|---|
| `train` | 630人 | あり | あり |
| `challenge` | 270人 | あり | なし（採点側だけが持つ） |

`Survived`は`0`が非生存、`1`が生存です。1行が乗客1人、1列がその人についての一項目です。

## 授業の9問

学生用Webページと[R/titanic_pipeline.R](R/titanic_pipeline.R)は、同じ順序で進みます。

| 問 | すること | 主なRコード |
|---:|---|---|
| 01 | 二つの表の人数を確認 | `nrow()` |
| 02 | 列名を確認 | `names()` |
| 03 | 0/1の平均から基準点を置く | `mean()` |
| 04 | Ageの欠損を数え、今回は使わないと決める | `is.na()`、`sum()` |
| 05 | Pclassを1等・2等・3等の区分にする | `factor()` |
| 06 | SexとSurvivedの人数表を見る | `table()` |
| 07 | PclassとSexから0/1用の規則を学ぶ | `glm()` |
| 08 | challengeの確率を0/1へ変える | `predict()`、`ifelse()` |
| 09 | PassengerIdと予測をCSVにする | `data.frame()`、`write.csv()` |

新しい関数や記号は、コード内の日本語コメントでも一行ずつ説明しています。問07の長い係数表、Ageの補完、交互作用は、今回の必須範囲には入れていません。

## Round 1とRound 2

Round 1では、全員が同じ基本モデルから始めます。

```r
Survived ~ Pclass + Sex
```

最初のscoreを見たら、`DECISIONS.md`へ変更理由と予想を書き、次のどれか**一つだけ**を試します。

- 問07のformulaへ`Fare`を追加する
- 問07のformulaへ`SibSp`を追加する
- 問07のformulaへ`Parch`を追加する
- 問08の判断境界`0.5`を`0.4`へ変える
- 問08の判断境界`0.5`を`0.6`へ変える

変数を追加した場合は問07→08→09、判断境界だけを変えた場合は問08→09を順に再実行します。複数箇所を同時に変えると、何がscore差を生んだか分からなくなるため、一つだけにします。

scoreが上がらないことも重要な結果です。「何を試し、なぜ試し、何が起きたか」を残すことが分析です。

## repositoryの中身

`repository`は、ある課題に関係するファイルと変更履歴をまとめた場所です。

```text
.
├── README.md                 # 今読んでいる説明書
├── data/
│   └── raw/
│       ├── titanic_train.csv
│       └── titanic_challenge.csv
├── R/
│   └── titanic_pipeline.R   # 読み込みから提出までのRコード
├── output/                  # Rが作る提出CSVの置き場所
├── DECISIONS.md             # 変更理由と結果の記録
└── docs/                    # ブラウザ実習・採点ページ
```

GitHubは完成品だけを置く場所ではありません。

- `repository`：分析全体のフォルダ
- `commit`：意味のある変更に名前を付けたチェックポイント
- `diff`：変更前と変更後の差
- `history`：どんな判断で分析が変わったかの記録

第3回では最後に教員のcommit、diff、historyを読みます。学生自身のGitHub登録とcommitは、準備時間を取れる別の回に行います。
