REGRESSION → LOGISTIC REGRESSION

回帰とは何か：集団ごとの割合を、一つの規則にまとめる

「回帰で予測する」と聞くと難しそうだが、出発点はただの割合である。まず式の前に、trainを集団ごとに数えた表を一つ見てほしい。

trainの630人を集団に分けて、生存した割合を数えた表
集団trainで生存した割合
female全体154 / 243 ＝ 約63%
male全体164 / 387 ＝ 約42%
1等のfemale48 / 55 ＝ 約87%
3等のmale72 / 206 ＝ 約35%
この割合そのものが、すでに素朴な予測であるfemaleの63%が生存しているなら、「challengeのfemaleは生存しやすいだろう」と見積もれる。等級も組み合わせれば、もっと細かく見積もれる。ただ、集団を細かく割るほど表は大きくなり、一つ一つの集団の人数は減って割合が当てにならなくなる。そこで登場するのが回帰である。回帰とは、この割合の表を、全員に共通して使える一つの式（規則）へまとめる方法である。式の中の数字——各手がかりが結果をどれだけ動かすかを表す重み——を係数と呼ぶ。
この先の式は、覚えなくてよいここから式が二つ出てくるが、導出や暗記は必要ない。読み取ってほしいのは「手がかり → 点数 → 確率」という流れと、二枚の図だけである。

普通の回帰：数値を直線で予測する

ŷ = a + b × x

回帰の一番簡単な形である。ŷは予測する試験の点数、aは直線の出発点、bは勉強時間が1増えたときの傾きである。一人ひとりの点はばらついているが、全員のまん中を通る直線を一本引けば、新しい人の勉強時間からでも点数を見積もれる。答えが点数のような連続した数値なら、これで十分である。

ロジスティック回帰：0/1を確率で予測する

z = b0 + b1 × 等級 + b2 × malep = 1 ÷ (1 + e−z)

ところが今日の答えは、点数ではなく生存の0/1である。0/1へ直線をそのまま使うと、予測が0未満や1より大きくなってしまう。そこで一段階はさむ。まず手がかりを一つの点数zにまとめ、次にS字の式でその点数を0〜1の確率pへ変換する。これがロジスティック回帰である。式に出てくるeはS字を作るための定数で、値を覚えたり手計算したりする必要はない。性別は、femaleをmale = 0、maleをmale = 1という数字にして式へ入れる。

なぜ0/1の問題には、S字の変換が必要なのか

普通の直線−0.2　←　0　…　1　→　1.3

直線はどこまでも伸びるため、「確率−0.2」や「確率1.3」のような解釈できない値を出せてしまう。

ロジスティック回帰のS字0　≤　確率 p　≤　1

どのような点数zでも0から1へ収められるため、生存しそうな程度を確率として読める。

重み付き点数の式を、日常の言葉で読む

z = b0 + b1 × Pclass + b2 × male

b₀出発点

どの乗客にも共通する基準の点数である。

b₁ × Pclass等級の分だけ動かす

等級の数値に、trainから学ぶ重みを掛ける。掛け算は、この手がかりが点数をどれだけ動かすかを表す。

b₂ × maleカテゴリーの差を加える

femaleなら0、maleなら1である。0を掛ければ差は加わらず、1を掛ければ重みが一回分加わる。

b₀, b₁, b₂全員に同じ重み

Rがtrainから決め、すべての乗客へ同じ値を使う。手で計算する必要はない。

trainの一行が、規則を直す方向を教える

仮の重みから確率を出し、trainにある既知の答えと比べる。次の0.40と0.70は、調整の考え方だけを示す仮の値である。

HOW SCORES MOVE

      
スコアはどこを変えると動くのか

      
提出するとAccuracyが返ってくる。では、その数字を上げたいとき、どこをいじればよいのか。今日の分析で調節できる場所は、次の三つである。

      

        
① 予測に使う列（STEP 1のformula）
Survived ~ Pclass + Sexの右側である。今日は二列に固定するが、次回以降は+ Ageや+ Fareのように、CSVにある列を自分で選んで足していく。ここを変えるとmodelから作り直しになるので、STEP 1 → 2 → 3を順に再実行する。なお、列を足せばスコアが必ず上がる、というものではない。それも実験で確かめることの一つである。

        
② 確率を0/1へ変える境界（STEP 3の数字）
0.5と書いた境界である。ここを上げ下げすると、確率は一切変わらないまま、提出する0/1だけが変わる。変えるのがSTEP 3だけなら、再実行もSTEP 3だけで済む。今日の2回目の提出では、これを動かす。

        
③ 表に入っていない情報
同じ等級・性別なのに結果が違う人たちがいた。その違いを説明する情報は、今の表の外にある。新しい情報を集めて表へ加えることも、スコアを動かす大きな手段である。これは最後の章と、この後の講義であらためて考える。

      

      
共通のルール：上流を変えたら、そこから下流を流し直す三つのSTEPは「model → probability → prediction」と一列につながった、川の流れのようなものである。上流のSTEPを変えたら、そこから下のSTEPをすべて作り直す。formulaを変えたらSTEP 1から、境界を変えたらSTEP 3だけ。このページも同じルールで、上流を編集すると下流の結果を自動的に無効にする。

      
そして、実際のデータ分析はこの「変えて、流し直して、また採点する」を何度も回す。この一周を分析のサイクルと呼ぶことにする。

      

        
1　考える仮説を立てる
「境界を0.6にしたら上がるはずだ」のように、変える場所と理由を決める
→
        
2　変えるコードを直して再実行
変更した場所から下のSTEPを流し直す
→
        
3　試す提出して採点
新しい予測を採点サーバーへ送る
→
        
4　振り返る前回と比べ、次の仮説へ
スコアの差を読み、1へ戻る

      

      
Kaggleの参加者は、この一周を何十回も回している一回の提出で終わりではなく、結果を見ては仮説を立て直し、少しずつスコアを詰めていく。今日はRound 1 → Round 2の2回の提出で、このサイクルをちょうど一周だけ体験する。

    


    

      
SECOND TRY

      
2回目の提出：サイクルを一周する。変えるのはSTEP 3の境界だけ

      
前の章で見た三つの調節場所のうち、今日は②の境界を動かす。手順は次のとおり。

      
    
        
  1. 1
    最初は0.5のままSTEP 1 → 2 → 3を実行し、提出する（Round 1）。
  2. 2
    STEP 3へ戻り、コード中の0.5を0.6へ変える。
  3. 3
    実行する前に、「0.6以上だけを1にすると、1の人数とAccuracyはどうなるか」を自分なりに予想する。
  4. 4
    STEP 3をもう一度実行する。ページが古い答案を破棄し、新しい答案へ置き換える。
  5. 5
    同じニックネームで2回目を提出し（Round 2）、二つの結果を比べる。
    6. 
      

      
なぜ、一度に一箇所しか変えないのか二箇所を同時に変えてスコアが動くと、どちらの変更が効いたのか分からなくなるからである。一箇所だけ変えれば、スコアの差はその変更のせいだと言える。これは理科の実験で条件を一つずつ変えるのと同じ考え方で、分析のサイクルを回すときの基本の作法である。

      
なぜ境界を0.6にするのかSTEP 2の確率を思い出してほしい。2等のmaleが約0.489、3等のfemaleが約0.509と、多くの乗客の確率が0.5のすぐ近くに集まっていた。境界を0.5から0.6へ動かすと、この「際どい人たち」の0/1がまとめて入れ替わる。つまり、小さな変更でも提出内容が大きく変わる、面白い場所である。

      
2回目も再計算は上から走るが、確率は同じ値になるSTEP 1と2のコードは変えていないので、作り直したmodelとprobabilityは1回目と同じ内容である。変わるのはpredictionだけ。「確率は同じでも、境界しだいで提出する0/1は変わる」ことを、自分の提出で確かめよう。
